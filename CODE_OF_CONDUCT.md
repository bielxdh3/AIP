# Code of Conduct

## Our standard

AIP should remain a productive technical space. Contributors and maintainers are expected to communicate respectfully, focus criticism on the work, and make room for evidence-based disagreement.

Expected behavior includes:

- constructive technical feedback;
- clear disagreement without personal attacks;
- good-faith questions and corrections;
- respect for privacy and security boundaries;
- protecting credentials, private data, and unpublished security details.

Unacceptable behavior includes:

- harassment, threats, discriminatory abuse, or targeted personal attacks;
- doxxing or publishing private information;
- deliberate exposure of credentials or private user data;
- spam or sustained bad-faith disruption;
- knowingly misleading security or validation claims.

## Scope

This policy applies to issues, pull requests, reviews, project discussions, and other public AIP project spaces.

## Enforcement

Maintainers may edit, hide, lock, or remove content; reject contributions; or restrict participation when necessary to protect contributors and the project.

Security vulnerabilities should follow [SECURITY.md](SECURITY.md), not public conduct-reporting channels.

For sensitive conduct concerns, contact the repository owner privately through GitHub.
